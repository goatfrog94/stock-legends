# STOCK LEGENDS

제시 리버모어 · 윌리엄 오닐 · 마크 미너비니의 매매 원칙을 30년 일봉 차트로 체득시키는
주식 투자 시뮬레이션. 미국·한국·일본의 실제 주도주 44종목을 익명화해 매 판 6~10개씩 뽑는다.

## 실행

```bash
node tools/serve.mjs
```

http://localhost:8123 접속. (`file://` 로 열면 브라우저가 fetch를 막는다.)
개발용 토글은 `?debug=1` 로 접속해야 보인다.

## 파이프라인

```bash
node tools/fetch-data.mjs        # Yahoo + 네이버 → data/raw/*.json
node tools/inspect-raw.mjs       # 재수집 없이 길이·결측 검사
node tools/build-game-data.mjs   # 캘린더 최적화 + 창 선택 + 오버레이 → manifest.json + data/w/*.json
node tools/validate.mjs          # 오버레이 수치 검증
node tools/exp-memorization.mjs  # 암기 방지 측정
```

### 일본을 뺀 이유

30년 일봉을 주는 일본 소스가 **미국 상장 ADR밖에 없다.** Yahoo의 `.T` 티커는 2000년부터만
제공하고, 한국의 네이버 같은 대안 소스도 없다. 그런데 ADR은 도쿄 장 마감 후 이미 정해진
가격을 따라 뉴욕에서 거래되고 거래량도 본토보다 훨씬 적어서

- 일간 고저폭이 **1.17%로 미국(2.31%)의 절반** — 캔들 느낌이 눈에 띄게 다르다
- 1980~90년대 구간은 OHLC가 부실하다 (고마츠는 30.6%의 날이 "하루 종일 한 가격",
  닛산은 아랫꼬리 없는 날이 56.3%) → 품질 게이트에서 이미 탈락

품질 게이트를 통과한 4종목(소니·도요타·혼다·히타치)도 "조용한 차트"라 위화감이 남아
통째로 뺐다. 정의와 원본 데이터는 남겨뒀다 (`tools/universe.mjs`의 `EXCLUDED_JP`).
되살리려면 `UNIVERSE`에 다시 넣고 `index.html`의 일본 쿼터를 복구하면 된다.

**가격 기준을 두 소스에서 반드시 통일해야 한다.**

| | 액면분할 | 배당 |
|---|---|---|
| Yahoo `adjclose` | 반영 | 반영 |
| Yahoo `quote.close` ← **사용** | 반영 | 미반영 |
| 네이버 수정주가 ← **사용** | 반영 | 미반영 |

`adjclose`를 쓰면 미국·일본 종목에만 배당 재투자가 붙어 한국 종목이 부당하게 불리해진다.
그래서 전체를 **「액면분할 반영 · 배당 제외」** 로 맞췄다. 배당은 별도 구현하지 않는다.

> 제외: HMM(30년 미달), 몬스터베버리지(6,521배 · 상한 초과), 일본 7종목 전체
> 네이버 엔드포인트는 공개돼 있지만 공식 API는 아니다. 개인 프로젝트 범위를 넘어 배포할
> 계획이면 KRX 정보데이터시스템 등 정식 경로를 확인할 것.

## 핵심 아이디어: 매크로 오버레이

종목마다 실제 시대가 다르면(시스코 1995~, 삼성전자 1995~) 게임 안에서 폭락 시점이 제각각이라
"시장 방향"이라는 개념 자체가 성립하지 않는다. 오닐의 M(Market Direction)을 가르칠 수 없다.

그래서 **원래 시장을 벗기고 게임 시장을 입힌다.**

```
lk(t)  = β(t) · ( R게임(t) − R원지수(t) )        하루치 조정 (±10% 클램프)
cum(t) = Σ lk(t)  →  로그선형 디트렌드 → cum(끝)=0
A(t)   = exp(cum'(t))
O,H,L,C 전부 × A(t)                              하루 안에서는 같은 배수
```

- `cum(끝)=0` 이라 **30년 총수익률이 원본 그대로 보존**된다 (검증 오차 0.00000%p)
- 하루 전체에 같은 배수 → **캔들 몸통/꼬리 비율과 갭이 완벽히 보존**된다 (VCP·컵앤핸들 생존)
- 매크로 충격이 **오버나잇 갭**으로 들어온다 (실제 시장과 동일)
- β가 곧 종목 성격이 된다 — 방어주는 위기에 덜 빠지고 강세장에서 덜 오른다

참조 지수(벗겨낼 원래 시장)는 미국 상장 = S&P 500, KRX = 코스피.

## 창 선택: 두 제약을 동시에 푼다

**① 총수익 밴드** — 한 종목이 유니버스를 지배하면 안 된다.
시스코는 30년 창을 어디서 자르느냐에 따라 **19배 ~ 810배**까지 갈린다.
종목별로 총수익 배수의 상하한을 건다 (`universe.mjs`의 `band`).

**② 위기 정렬** — 종목의 폭락이 게임 위기 창에 겹쳐야 한다.
겹치지 않으면 오버레이가 오히려 폭락을 상쇄해 시그니처 붕괴가 뭉개진다.

두 제약은 충돌한다. 그래서 종목 오프셋만이 아니라 **위기 캘린더 자체도 함께 움직여** 좌표
하강으로 푼다 (`optimizeCalendar`). 현재 빌드는 통화 위기를 1.4년 앞당겨 맞췄고, 밴드 미달 0개다.

## 캔들 품질 게이트

1980~90년대 일본 ADR처럼 거래가 뜸한 구간은 **OHLC가 제대로 안 채워져 있다.**
시가=종가인 날이 30%씩 나오고 고가만 따로 찍혀서 "몸통 없이 윗꼬리만 긴 캔들"이 된다.
오버레이는 하루 전체에 같은 배수를 곱하므로 이 등호 관계가 그대로 보존된다 → **원본에서 걸러야 한다.**

창 선택 조건에 누적합 기반 품질 게이트를 넣었다 (`qualityPrefix`, O(1) 구간 조회).

| 지표 | 상한 | 뜻 |
|---|---|---|
| `flat` | 1.5% | 하루 종일 한 가격 (고가=저가) |
| `noBody` | 10% | 시가=종가 |
| `noUp` / `noDn` | 30% | 윗꼬리 / 아랫꼬리가 아예 없음 |

임계값은 감이 아니라 실측 분포에서 잡고(`exp-candle-shape.mjs`),
기준별 비용을 재서 정했다(`sweep-quality.mjs`). 당시 측정에서 **비용은 전적으로 일본이
치렀고** 미국·한국은 어느 기준에서도 한 창도 줄지 않았다 — 이게 일본을 통째로 뺀 근거가 됐다.

게이트의 1차 효과는 종목을 버리는 게 아니라 **다른 창을 고르게 만드는 것**이다
(고마츠 1986창 → 1994창, 소니 1977창 → 1980창). 그래도 쓸 만한 구간이 없으면 탈락한다.

현재 상태 (미국 + 한국, 55창)

| 지표 | 중앙 | 상위 10% |
|---|---|---|
| `flat` | 0.0% | 0.1% |
| 시가=종가 | 4.1% | 7.3% |
| 윗꼬리 없음 | 13.8% | 23.2% |
| 아랫꼬리 없음 | 13.2% | 22.0% |

시장별 일간 고저폭: 미국 2.31% · 한국 2.71%.

**최소 일간 변동폭 게이트는 넣지 않는다.** 저변동은 결함이 아니라 β 학습 소재다
(미국 방어주는 존슨앤드존슨 1.35%, 코카콜라 1.38%, 서던컴퍼니 1.44%).
이걸 자르면 방어형 종목이 같이 죽는다.

**절대 상한** — 밴드를 못 맞춰 폴백하더라도 총수익 300배를 넘으면 종목을 통째로 버린다.
8종목 유니버스에 수천 배짜리가 하나 끼면 나머지 판단이 전부 무의미해진다.
(몬스터베버리지는 품질 게이트가 초기 저유동성 구간을 걸러내자 1995년 창만 남았고
그게 6,521배라 탈락했다.)

> **고칠 수 없는 것**: 일본 ADR은 일간 고저폭이 1.27%로 미국(2.32%)의 절반이다.
> 도쿄 장 마감 후 뉴욕에서 이미 정해진 가격을 따라 거래되는 데다 거래량도 훨씬 적어서
> 장중 변동이 원래 작다. 데이터 결함이 아니라 실제 성질이므로 그대로 둔다.
> 일본 종목은 "조용한 차트"로 나온다.

## 다중 창 — 한 종목에서 여러 종목

여유가 8년(2,000봉) 이상인 종목은 **겹치지 않는 창 2개**를 뽑아 별개 종목으로 등록한다.
GE·제록스·코카콜라·맥도날드 등은 여유가 26년이라 두 창이 사실상 완전히 다른 종목이 된다.

**37종목 → 55개 창.** 2번째 창이 총수익 밴드를 초과하면 만들지 않는다
(마이크로소프트 275배, 어도비 290배는 생략됨).

## 매 판 유니버스 추첨

`manifest.json`을 먼저 읽고, 뽑힌 창만 `data/w/<code>.json`으로 지연 로드한다.
(전체 38MB지만 실제 다운로드는 창 1개당 약 700KB)

**매니페스트는 완전히 익명이다.** 공개 배포하면 누구나 개발자 도구로 볼 수 있으므로,
추첨에 꼭 필요한 네 개만 남기고 실명·실제기간·수익배수는 전부 창 파일 안에 둔다.

```json
{ "code": "0h0fgub", "grp": "1wpc6io", "mkt": "US", "archetype": "붕괴형" }
```

- `code` — 창 식별자이자 파일명. 파일명에 티커가 드러나면 익명화가 무의미해진다
- `grp` — 같은 실제 종목인지만 알려주는 불투명 키 (한 판에 같은 종목 두 창 방지용)
- 솔트가 고정이라 다시 빌드해도 코드가 같다 → 진행 중인 세이브가 깨지지 않는다

- **6~10종목** 랜덤
- 같은 종목의 다른 창을 두 개 뽑지 않는다
- 쿼터: 승자군(폭발/우상향) 2, 패자군(붕괴/쇠퇴) 2, 방어형 1, 한국 1
- 게임 내 이름은 고정 풀 24개에서 매 판 무작위 배정. **업종은 숨긴다**
  ("반도체"라고 뜨면 "사이클형"이라는 힌트가 된다)

## 워밍업

게임은 `day = 250`(워밍업 1년 후)에서 시작한다. 시작하자마자 1년치 차트가 깔려 있어
200일선과 52주 신고가를 처음부터 쓸 수 있다. 벤치마크 기준점도 전부 이 시점이다.

## 화면 보간

일봉을 그대로 쓰면서 눈에 보이는 것만 부드럽게 만든다.
**체결·손절·벤치마크는 전부 정수 `day` 기준이고, 화면만 실수 `viewDay` 기준이다.**

| 기법 | 하는 일 |
|---|---|
| 서브픽셀 연속 스크롤 | `viewDay`가 `day`를 지수 보간으로 따라가며 차트가 픽셀 단위로 흐른다 |
| y축 스케일 보간 | 신고가마다 차트 전체가 출렁이던 것을 없앤다 |
| 마지막 봉 성장 | 새 봉이 시가에서 시작해 고가/저가로 벌어지며 종가로 수렴한다 |

`viewDay = t` 는 "봉 `ceil(t)` 가 `t − ceil(t) + 1` 만큼 진행된 상태"를 뜻한다.
정지하면 `viewDay`가 `day`로 수렴해 **표시가가 종가와 정확히 일치**한다.
`viewDay ≤ day` 이므로 미래 데이터는 어떤 경우에도 보이지 않는다.

체감 튜닝 파라미터: `VIEW_TAU`(0.085), `SCALE_TAU`(0.20).

## 액면분할

수정주가로 통일하면 분할이 사라져 30년 뒤 주당 3,494만원이 된다. 초기자본 1,000만원으로
1주도 못 산다. 실제 시장이 하는 대로 되살렸다.

- 가격은 "분할 전 연속 단위"로 저장, 날짜별 누적배수 `divAt[]`만 따로 둔다
- 표시가격 = `c[t] / divAt[현재일]`, 표시수량 = `내부수량 × divAt[현재일]`
- **내부 계산은 분할일에 아무것도 바뀌지 않는다** → 자산 점프 0%
- 로그차트 모양은 그대로, 축 숫자만 내려간다 (실제 증권사와 동일한 소급 조정)

## 벤치마크

**시장지수 대비 알파 하나가 유일한 성적표다.** 동일가중 지표들은 좌측 하단 참고용.

초기에 "동일가중 B&H 대비" 등급을 제안했다가 접었다. 그건 *어느 게 대박인지 미리
알았을 때*의 수익이라 실력으로 도달 가능한 기준이 아니다.

## 포트폴리오 패널

종목당 비중 제한을 두지 않으므로, **제한하는 대신 보여준다.**

- 비중 바 (현금 + 종목별 색 세그먼트)
- 종목별 평가금액 · 비중 %
- **계좌 리스크** — 지금 그어둔 손절선이 전부 걸렸을 때 잃는 총액. 손절선 없는 보유 종목은 경고
- 최대 낙폭(MDD) 실시간 추적
- 손절 패널은 **현재가 대비**와 **평단 대비**를 나눠 보여준다.
  주문과 체결 사이 갭이 나면 크게 벌어진다 (실측: −8.00% vs −13.68%)

| 액면분할 | 켬 |

같은 종목·같은 사유는 재알림 간격(짧게 10 / 보통 20 / 길게 40 거래일)을 둬 도배를 막는다.

**이 설정이 사실상 플레이타임 다이얼이다.** 30년 순수 진행은 10배속에서 3분인데,
정지 한 번에 10초씩만 써도 정지 횟수가 총 소요시간을 결정한다.

| 설정 | 1,500일당 정지 |
|---|---|
| 전체 켬 | 135회 |
| 마스터 끔 | 0회 |
| 신고가만 | 48회 |
| 신고가만 + 간격 길게 | 26회 |

> **고쳤던 버그**: 손절 체결과 액면분할 알림이 `autoPause` 조건 바깥에 있어서
> 껐는데도 계속 멈췄다. 껐는데 멈추면 기능이 없는 것과 같다.
> 지금은 체결·분할 같은 실제 사건은 그대로 일어나되 **알림만** 설정을 따른다.
> 버튼 표시도 `syncPauseUI()` 한 곳에서만 그려 상태와 어긋나지 않게 했다.

## 성능

M1에서 3배속 이상일 때 "버벅이고 종목 전환이 안 되던" 문제의 원인은 CPU가 아니었다.
관심종목·보유목록을 매 틱 `innerHTML`로 통째 재생성 → **초당 12번 DOM 파괴** →
mousedown과 mouseup 사이에 노드가 사라져 클릭이 유실됐다.
DOM은 한 번만 만들고 텍스트만 갱신하도록 바꿨고, 종목 전환은 `pointerdown`에서 즉시 처리한다.

현재 프레임 비용: 250봉 0.22ms, 2500봉 1.33ms.

## 채택하지 않기로 한 것

- **전설 도감 / 정체 간파 시스템** — 암기를 콘텐츠로 흡수하는 메타 진행. 미채택
- **종목당 최대 비중 제한** — 플레이어가 자기 스타일대로 판단하게 두고, 몰빵의 리스크와
  손실을 직접 겪으며 배우도록 한다. 미채택
- **배당 별도 구현** — 소스 간 기준 통일 문제로 전체를 배당 제외로 맞췄다

## 암기 방지 측정치

같은 종목을 오프셋·위기 캘린더만 바꿔 변형을 만들고 로그가격 경로 상관계수를 쟀다.

| 비교 | 상관계수 |
|---|---|
| 같은 시스코, 변형끼리 (오버레이 ON) | 0.83 ~ 0.88 |
| 같은 시스코, 오프셋만 벌림 (6.7년 차이) | 0.571 |
| 시스코 ↔ AMD | 0.356 |
| 시스코 ↔ 한국전력 | 0.173 |

**0.87은 사실상 같은 차트다.** 이름을 바꿔도 알아본다. 역설적으로 오버레이는 변형 간
유사도를 *높인다* — 모든 변형에 같은 시장 리듬을 주입하는 게 목적이라 위장과 상충한다.
그래서 다중 창(8년 이상 오프셋 차이)이 실질적인 대응 수단이다.

## 알려진 이슈

1. **UI 육안 검증 미완** — 개발 환경에서 브라우저 패널이 프레임을 그리지 않아 스크린샷을
   못 찍었다. DOM 값 검사와 스크립트 구동으로만 검증됨. 특히 화면 보간의 체감은 확인 필요.
2. **사이클형이 23개로 편중** — 67창 중 34%. 쿼터로 완화되지만 유형 재분류 여지가 있다.
3. **자동정지 빈도** — 3종목 기준 335회. 6~10종목이면 비례해 늘어나므로 재튜닝 필요.
4. **온보딩 부재** — 손절선·포지션 사이징이 증권사에 없는 개념이라 처음 보면 용도를
   알기 어렵다. 플레이해 보고 판단하기로 유보.
